# Profiles (free scope) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the free subset of `docs/superpowers/specs/2026-08-20-profiles-design.md`: multiple applicant profiles, a simple shared "About you" block, client-side file import, a draft-time profile picker, a subject pattern, and backup v3 — replacing the single profile.

**Architecture:** Two new local stores (`about.js`, `profiles.js`) plus a pure `subject.js` and an options-only `import-file.js`. The old `profile.js` shrinks to the legacy shape used only by migration + backup-v2. The options page gets an About card, a profile list, and a profile editor. The draft panel gains a profile `<select>`; `buildDraftProfile(about, profile)` shapes what the draft sends. The site's `buildPrompt` gains an About block (flat fields + links). No new server route, no ledger change.

**Tech Stack:** MV3 extension, ES modules, vitest (+ jsdom); React 18 + Vite options page; `pdfjs-dist` + `mammoth` (options only, dynamic-imported). Site: Next.js route handler already exists; only `drafting.ts` + `validation.ts` change.

## Global Constraints

- Free scope only. **No** `certifications`, `testimonials`, `exclude`, per-profile toggles, template/prompt editing — those are premium/deferred (`free-premium-split` memory).
- Local storage only; the raw uploaded file is never stored or uploaded — only its extracted markdown. Email and phone never go to the model.
- Exactly one profile is `isDefault`. Migration from the single profile runs once and is idempotent.
- Tests green before each commit; one commit per task, per repo.

## Data shapes (verbatim)

- `ojRateFilterAbout`: `{ name, email, phone, location, timezone, availability, equipment, languages, other, links: [{id,label,url}] }` — flat strings capped (line 200 / short 120 / other 2000); `links` cap 20.
- `ojRateFilterProfiles`: `[{ id, label(<=80), headline(<=200), targetRoles: string[](<=30), body(<=20000 md), source: 'typed'|'pdf'|'docx'|'text', isDefault: bool, updatedAt: number }]` — cap 12.
- Stored draft (drafts.js) gains `profileId`.
- Settings add: `draftProfileId: ''`, `draftSubjectPattern: 'Application: {jobTitle} — {name}'` (both sync).
